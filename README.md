# Лист — поиск по документам

Первая рабочая версия приложения для курсовой «Поисковая система по документам на основе векторного поиска».
Python + FastAPI + Jinja2; PostgreSQL + pgvector; миграции Alembic; локальная многоязычная модель E5.

## Что уже умеет

- Вход и самостоятельная регистрация по логину и паролю; роли reader, editor и admin из отдельного справочника.
- При регистрации создаётся читатель с доступом к общим коллекциям. Доступ к закрытым администратор выдаёт через «Управление».
- Управление коллекциями, категориями, пользователями и доступом к коллекциям.
- Загрузка TXT (UTF-8 / Windows-1251), DOCX и PDF с текстовым слоем.
- Обработка документов отдельным worker-процессом: текст, фрагменты с перекрытием, эмбеддинги.
- Поиск по словам, по смыслу и гибридный поиск с объединением по позициям RRF.
- Фильтры по коллекции и категории, просмотр фрагментов, скачивание источника.
- Изменение названия и категорий, повторная обработка и удаление документа.
- Проверка доступа при поиске, просмотре, скачивании и изменении.
- Серверные HTML-страницы и обычные формы. Отдельного JSON REST API, Swagger и frontend-фреймворка нет.

Векторный поиск пока точный, без ANN-индекса. Это удобный исходный вариант для сравнения с HNSW/IVFFlat в следующих этапах. Результат — найденные фрагменты, а не сгенерированный ответ нейросети.

## Обновление уже установленного приложения

Распакуйте новый архив поверх прежней папки `vector_search_app`, заменив исходники. В архиве нет `.env`, базы, загруженных документов и кеша модели: существующие настройки и именованные Docker-тома сохраняются. Используйте ту же папку `$HOME/Projects/vector_search_app` и прежнее имя проекта Compose. Не выполняйте `prepare_env.py` повторно.

```bash
cd "$HOME/Projects/vector_search_app"
docker compose build web
docker compose up -d --no-build --force-recreate migrate web worker
```

Повторно создавать администратора не нужно. Откройте `/login` или `/register`; если уже вошли, сначала выйдите. Для регистрации используется существующая таблица users. Миграция 0002 добавляет поле access_level в collections; существующие строки, документы и индивидуальные разрешения сохраняются, существующие коллекции остаются закрытыми. Логин регистрируется в нижнем регистре, от 3 до 100 символов; пароль от 10 до 256 символов. Проверяются повтор пароля, занятость логина и CSRF. Лимиты входа и регистрации отдельные: по 15 попыток за 5 минут на IP, в памяти одного web-процесса. Почта, подтверждение email и самостоятельное восстановление пароля не добавлены; пароль можно сменить через CLI.

## Смена роли пользователя на сайте

Войдите администратором → «Управление» → «Пользователи». В строке нужного пользователя выберите «Читатель», «Редактор» или «Администратор» и нажмите «Сохранить роль». Повышение и понижение действуют со следующего запроса даже в уже открытой сессии. Пароль, состояние учётной записи и персональные разрешения при этом не меняются.

Редактор изменяет документы в доступных ему коллекциях. Администратор получает доступ ко всем коллекциям и управлению архивом. Свою роль в интерфейсе менять нельзя; для этого нужен другой администратор. Изменение чужих ролей доступно только администратору и защищено CSRF. Для этой функции новая миграция не требуется: используется существующее поле users.role_id.

## Общие и закрытые коллекции

После обновления войдите администратором → «Управление» → «Видимость коллекций». Для нужной коллекции выберите «Для всех зарегистрированных» и нажмите «Сохранить доступ». Такая коллекция сразу доступна существующим и будущим активным пользователям: поиск, просмотр и скачивание. Гостям по-прежнему требуется вход. Регистрация создаёт читателя, не редактора.

Закрытая коллекция доступна администратору и пользователям с индивидуальным разрешением в collection_access. Если общую коллекцию закрыть, пользователи без персонального разрешения сразу потеряют доступ при следующем запросе. Персональные разрешения не удаляются. Отзыв индивидуального разрешения не блокирует общую коллекцию.

В pgAdmin после успешной миграции можно посмотреть:

```sql
SELECT collection_id, name, access_level
FROM docsearch.collections ORDER BY collection_id;
```

Значения поля access_level: `private` — закрытая; `registered` — для всех зарегистрированных. Выбор в интерфейсе изменяет это же поле, поэтому вручную создавать столбец не требуется. Роли по-прежнему ограничивают изменение документов: читатели не могут загружать или удалять их.

## 1. Самый простой запуск на Mac через Docker

Нужны Docker Desktop с работающим Docker Engine, Python 3 и интернет для первого скачивания образов, Python-библиотек и модели. Docker-сборка с PyTorch занимает несколько минут и несколько ГБ диска. Модель отдельно занимает около 0,5 ГБ и кешируется.

Распакуйте архив. В Терминале перейдите в папку `vector_search_app`:

```bash
cd /путь/к/vector_search_app
python3 prepare_env.py
docker compose up --build -d
```

`prepare_env.py` создаст `.env` со случайными секретами. Повторно существующий файл не перезаписывается. Не публикуйте `.env`.

Общий образ собирается только сервисом web; migrate и worker используют этот же готовый образ. В Dockerfile права исходников приводятся к читаемым для appuser, в том числе после копирования с флешки macOS.

Compose поднимает четыре сервиса:

| Сервис | Назначение |
|---|---|
| db | PostgreSQL 15 с pgvector 0.8.7 |
| migrate | Однократное применение недостающих миграций |
| web | Страницы приложения, порт 8000 |
| worker | Отдельный процесс обработки документов |

Впервые создайте администратора:

```bash
docker compose exec web python -m app.cli create-admin
```

Введите логин, отображаемое имя и пароль длиной не менее 10 символов. При вводе пароля символы не отображаются — это нормально. Готовых учётных записей и общих паролей в проекте нет.

Откройте **http://localhost:8000**. Войдите, откройте «Управление» и создайте коллекцию. Затем загрузите документ через «Загрузить».

Можно заранее скачать модель:

```bash
docker compose exec worker python -m app.cli download-model
```

Иначе она скачается при первой обработке или первом поиске по смыслу. Векторы вычисляются на CPU локально; текст документов не отправляется во внешний embedding API.

### Проверка состояния и журналы

```bash
docker compose ps
docker compose logs --tail=100 migrate
docker compose logs --tail=100 worker
docker compose logs --tail=100 web
```

При ошибке обработки её краткое описание видно редактору на странице документа. Исправив причину, нажмите «Обработать заново». Для обновления состояния нажмите «Обновить страницу».

Остановка с сохранением данных:

```bash
docker compose down
```

Повторный запуск:

```bash
docker compose up -d
```

Не используйте `docker compose down -v`, если хотите сохранить базу, загруженные документы и кеш модели. Данные лежат в именованных томах `postgres_data`, `uploads`, `model_cache`.

### Подключение pgAdmin к Docker-БД

Это ОТДЕЛЬНАЯ база в контейнере. Она не заменяет и не переносит автоматически существующую Homebrew-БД.

| Настройка | Значение |
|---|---|
| Host | localhost |
| Port | 5433 |
| Database | document_search |
| Username | docsearch |
| Password | значение POSTGRES_PASSWORD из локального .env |

Порт 5433 выбран, чтобы не конфликтовать с PostgreSQL на порту 5432. Приложение обращается к контейнеру по внутреннему имени `db`, а pgAdmin — к опубликованному порту 5433.

## 2. Запуск с вашей существующей PostgreSQL 15 / Homebrew без Docker

Подходит для уже созданной БД `document_search`. pgvector должен быть установлен и доступен серверу. Перед первым применением миграции сделайте резервную копию, например через pgAdmin → Backup.

В каталоге проекта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install torch==2.14.1 -r requirements-ml.txt
python prepare_env.py
```

Если Python 3.12 не установлен, сначала установите его; другой установленный Python не заменяется автоматически.

Откройте `.env` текстовым редактором и измените DATABASE_URL под вашу локальную БД:

```dotenv
DATABASE_URL=postgresql+psycopg://ВАШ_ПОЛЬЗОВАТЕЛЬ:ВАШ_ПАРОЛЬ@localhost:5432/document_search
```

Символы `@`, `:`, `/`, `#` и `%` в логине или пароле URL необходимо URL-кодировать. Не вставляйте сюда чужой или примерный пароль. Остальные секреты, созданные `prepare_env.py`, сохраните.

Выполните:

```bash
alembic upgrade head
python -m app.cli create-admin
```

Если логин уже существует, выберите другой; смена пароля выполняется отдельной командой:

```bash
python -m app.cli reset-password
```

Запустите web в первом окне Терминала:

```bash
source .venv/bin/activate
uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Во втором окне перейдите в тот же каталог, активируйте то же окружение и запустите worker:

```bash
source .venv/bin/activate
python -m app.worker
```

Откройте http://localhost:8000. Worker нужен для обработки файлов; без него документы останутся «В очереди».

## 3. Миграции и сохранение существующих данных

- `migrations/versions/0001_initial.py` создаёт согласованные 10 таблиц и триггеры.
- Файл `sql/initial.sql` основан на ранее выданном `Vector_Search_Create.sql`, но не содержит внешних BEGIN/COMMIT: транзакцией управляет Alembic.
- Если схема docsearch уже существует, миграция сначала сравнит столбцы, типы, обязательность, identity и определения ключей/CHECK/FK с ожидаемой схемой. При несовпадении завершится ошибкой до изменения таблиц.
- При совпадении существующие строки сохраняются, функции и триггеры приводятся к текущему описанию, затем фиксируется версия Alembic.
- Следующий `alembic upgrade head` ничего повторно не создаёт, если версия уже применена.
- Не используйте `alembic stamp head` вместо исправления несовпадающей схемы.
- Автоматический разрушительный downgrade отключён. Для отката используйте резервную копию.
- Миграция не переносит внешние исходные файлы и не превращает старые значения паролей в Argon2-хеши.

По умолчанию исходные файлы хранятся в `data/uploads`. Для существующих документов storage_key должен указывать на реальный файл внутри настроенного STORAGE_DIR. Если файлов раньше не было, загрузите документы заново через интерфейс. Если в БД есть хеши другого формата, задайте новый пароль через CLI.

При смене модели или её параметров создаётся другой неизменный профиль. Чтобы старые документы появились в векторном поиске новым профилем, выполните их повторную обработку. Поиск сравнивает векторы только одного профиля и не включает документы с неполным набором векторов для этого профиля.

## 4. Как проверить работу через интерфейс

1. Войдите администратором и создайте две коллекции, например «Учебные материалы» и «Личные документы».
2. Создайте категорию «Базы данных».
3. Создайте читателя и редактора; выдайте им доступ только к первой коллекции.
4. Загрузите TXT/DOCX/PDF в первую коллекцию. Дождитесь статуса «Готов».
5. Найдите фрагмент по точному слову, затем попробуйте перефразированный вопрос в режиме «По смыслу».
6. Откройте найденный фрагмент и скачайте оригинал.
7. Загрузите другой документ во вторую коллекцию. Читатель первой коллекции не должен видеть его даже по прямому адресу.
8. Измените название документа: повторное вычисление векторов не требуется.
9. Выполните повторную обработку и удаление документа; проверьте связанные строки через pgAdmin.

Оценки в выдаче не являются вероятностями. Косинусная оценка, полнотекстовый рейтинг и RRF имеют разные шкалы; их нельзя сравнивать между режимами напрямую.

## 5. Ограничения первой версии

- Приложение настроено для локального использования: порты привязаны к 127.0.0.1. Удалённый доступ пока не настроен.
- Для публикации нужны HTTPS, COOKIE_SECURE=true, настройка хостов/прокси и эксплуатационные проверки. Текущий доступ приложения к БД рассчитан на доверенный локальный запуск, без раздельных технических ролей web/worker/migrate.
- Один worker. Он удерживает advisory lock PostgreSQL; после перезапуска возвращает незавершённую обработку в очередь. Не масштабируйте worker произвольно.
- Web запускается одним процессом. Ограничение попыток входа хранится в памяти и сбрасывается при перезапуске.
- До 10 МБ на файл, 400 000 символов текста, 500 страниц PDF и 3000 фрагментов. Ограничения можно менять в настройках, но большие файлы требуют оценки ресурсов.
- OCR сканов, колонтитулы и текстовые поля DOCX, генерация ответов, предпросмотр PDF внутри окна и измерение качества на размеченном корпусе пока не реализованы.
- PDF: номер страницы обозначает начало фрагмента; сам фрагмент может захватывать текст следующей страницы.
- Модель специально выбрана для русскоязычных и многоязычных запросов. Профиль зафиксирован полным SHA commit. Для произвольной другой модели нужно проверить префиксы и алгоритм кодирования.
- Нет HNSW/IVFFlat, истории запросов, массового переноса внешних файлов и редактирования исходного текста через браузер. Это следующие этапы, а не скрытые имитации.
- Разрешения проверяются приложением. Пользователь, имеющий прямой административный доступ к PostgreSQL, может читать БД независимо от роли в интерфейсе.

## 6. Проверки кода

Быстрые тесты без сервера БД:

```bash
python -m pip install -r requirements-dev.txt
pytest -q tests/test_core.py
```

Интеграционные тесты используют ОТДЕЛЬНУЮ тестовую БД и очищают её таблицы. Никогда не указывайте рабочую БД:

```bash
export TEST_DATABASE_URL='postgresql+psycopg://USER:PASSWORD@localhost:5432/document_search_test'
export RESET_TEST_DATABASE=1
pytest -q
```

Для отдельной проверки настоящей модели установите ML-зависимости и добавьте:

```bash
RUN_REAL_MODEL=1 pytest -q -m real_model
```

Часть тестов подменяет кодировщик маленькими контролируемыми векторами, чтобы отдельно проверить доступ и SQL-логику. В рабочем приложении такой подмены нет. Тест настоящей модели проверяет обработку и поиск с 384-мерными E5-эмбеддингами; это проверка работоспособности, а не доказательство качества на всех документах.

## Структура проекта

```text
app/
  main.py          HTML-страницы и обработчики форм
  security.py      Пароли, сессии, CSRF и роли
  documents.py     Чтение документов и разбиение
  embeddings.py    Настоящая локальная модель E5
  search.py        Лексический, векторный и гибридный поиск
  worker.py        Обработка очереди документов
  cli.py           Создание администратора, пароль, загрузка модели
  templates/       HTML-шаблоны
  static/          CSS
migrations/        Версии схемы Alembic
sql/               Исходная схема и её проверяемое описание
tests/             Тесты
compose.yaml       Совместный запуск
prepare_env.py     Создание локальных секретов
```
